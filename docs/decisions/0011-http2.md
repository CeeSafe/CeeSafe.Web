# Web ADR 0011 — HTTP/2

**Status:** accepted 2026-11-03 (M7). §6's four questions were answered by the owner: TLS ALPN `h2` and cleartext
`h2c` by prior knowledge; the server only in M7; priority ignored, streams served fairly; server push supported.
**Scope:** implementation plan §7 M7: `web_http2` (RFC 9113 and RFC 7541), its driver, `Exchange`'s HTTP/2 variant, and
the server's choice of protocol.

## 1. Context

- **Web ADR 0004 §3.4 already fixes the shape.** One connection task owns the engine and the transport. Each request
  stream is a child task, and streams and the connection talk only through bounded channels: an inbox of DATA per
  stream, bounded by its receive window, and an outbox into the connection, bounded so that a fast handler waits for
  the flow-control window.
- **Streams come and go while the connection runs**, so their tasks are a task set's children (CeeSafe ADR 0053,
  released in 0.9.0 as upstream U11), not a scope's. A set child holds no loan: whatever a stream shares with the
  connection, the application included, it shares through `Arc` or a channel.
- **A set cancels its children only all at once.** One stream's RST_STREAM must cancel only its handler. So each
  stream task races its handler against its own reset channel. Probe `tests/probes/h2-stream-tasks.cee` checks all of
  this, interpreted and native: four streams in a set, sharing an `Arc<Box<dyn App + Send>>`, one cancelled by its
  reset while the others finish (`11`, then `1`).
- **Handlers are shared code.** `Application` (`web_http`) is what both drivers call, with a `Request` and an
  `Exchange`. Web ADR 0003 §3 planned `Exchange`'s HTTP/2 form: the body comes from the stream's inbox
  (`BodyFraming.Stream`), and writes go to the outbox.

## 2. Options

**How streams run.**

| | A. A task-set child per stream (proposed) | B. A fixed pool of stream workers per connection |
|---|---|---|
| Memory | a frame per live stream | a frame per worker, live or not, on every connection |
| Concurrency | up to SETTINGS_MAX_CONCURRENT_STREAMS | at most the pool's size; the rest wait |
| Sharing | through `Arc` | by borrow (scope children may borrow) |

M1 chose workers for connections when task sets did not exist. For streams, B would allocate the pool on every
connection, idle or not, or refuse useful concurrency. A, with `Arc`, costs one reference count per stream.

**HPACK's encoder.** The decoder must be complete (RFC 7541). The encoder may use any subset: using the static table
and literals only is always valid, needs no dynamic table size update whatever the peer announces, and keeps no
per-connection encoder state. Indexing response headers in the dynamic table saves bytes on repeated headers; it is a
compression decision for M9's benchmarks.

## 3. Decision

### 3.1 The engine (`web_http2`, sans-I/O)

- **HPACK** (`hpack.cee`, `huffman.cee`):
  - the decoder handles every representation, the dynamic table and its size updates, and Huffman;
  - its tables are generated from RFC 7541's text (`tools/gen_hpack_tables.py`), and its tests are every Appendix C
    example (`tools/gen_hpack_vectors.py`);
  - a list over SETTINGS_MAX_HEADER_LIST_SIZE is still decoded, so the table stays in step, then refused;
  - the encoder uses the static table and literals, Huffman-coded when shorter.
- **Frames** (`frame.cee`): the 9-byte header, the ten frame types, flags, error codes and settings, and a writer for
  each frame; a header block larger than the peer's SETTINGS_MAX_FRAME_SIZE goes out as HEADERS (or PUSH_PROMISE) and
  CONTINUATIONs.
- **The connection state machine** (next): the preface and SETTINGS exchange; the stream states of RFC 9113 §5.1,
  push's reserved states included; flow control (§5.2, §6.9); and the guards (§3.4). Bytes in, events and frames out.

### 3.2 The driver and `Exchange`

- **Entry.** Over TLS, ALPN `h2` selects HTTP/2; `web_tls` already offers it. Over cleartext TCP, a connection that
  starts with the client preface (`PRI * HTTP/2.0`, RFC 9113 §3.4) is HTTP/2 ("prior knowledge"), and any other is
  HTTP/1.1. The HTTP/1.1 `Upgrade: h2c` path, which RFC 9113 §3.1 deprecated, is not supported.
- **One connection task** owns the transport and the engine:
  - it reads frames and feeds the engine;
  - it starts each new request's stream task in the connection's task set;
  - it writes the frames streams queue, as flow control allows, taking DATA from the streams round-robin (priority
    signals are ignored: RFC 9113 §5.3.2 deprecated the tree, and RFC 9218 can come later).
- **A stream task** owns its request's head buffer and `Exchange`, shares the application through `Arc`, and races the
  application's `handle` against its reset channel.
- **`Exchange`** gets a variant for a stream: the body reads from the stream's inbox; writes queue HEADERS and DATA in
  the outbox, waiting for the window. A handler sees the same API as over HTTP/1.1.
- **Server push.** `Exchange.push(path, fields)`, when the client has not disabled it (SETTINGS_ENABLE_PUSH = 0):
  - the connection sends PUSH_PROMISE on the request's stream with the promised request's head;
  - the promised stream (reserved, then half-closed) runs the application's `handle` for that GET request in its own
    stream task, as if the client had asked for it.
- **Shutdown** follows M1's drain: GOAWAY with the highest stream ID, then, after a PING round trip, GOAWAY with the
  last stream started; streams in flight finish within the grace period, then the set is cancelled.

### 3.3 Settings and limits (defaults; `Limits` and the server's options can change them)

| Setting | Value |
|---|---|
| SETTINGS_MAX_CONCURRENT_STREAMS | 100; streams past it are refused with REFUSED_STREAM |
| SETTINGS_INITIAL_WINDOW_SIZE | 65535 per stream; a WINDOW_UPDATE once the handler has read half |
| the connection's window | raised to 1 MiB at the start |
| SETTINGS_MAX_FRAME_SIZE | 16384 |
| SETTINGS_HEADER_TABLE_SIZE | 4096 |
| SETTINGS_MAX_HEADER_LIST_SIZE | `Limits.maxHeaderBytes` |
| SETTINGS_ENABLE_PUSH | not sent: a server's value is meaningless (§6.5.2) |

### 3.4 The guards (acceptance criteria, implementation plan §8)

- **CONTINUATION flood** (CVE-2024-27316 class): a header block's encoded size across HEADERS and CONTINUATIONs is
  bounded (twice the header list limit). Past it, the connection is closed with ENHANCE_YOUR_CALM, without decoding
  the rest.
- **Rapid reset** (CVE-2023-44487): streams the client resets, or we refuse, count against a budget per interval.
  Past it, GOAWAY with ENHANCE_YOUR_CALM.
- **SETTINGS, PING and other control floods:** acknowledgements waiting to be written are bounded. A peer that sends
  faster than it reads them is closed with ENHANCE_YOUR_CALM.
- **Empty frames:** DATA without payload or END_STREAM, and zero-increment WINDOW_UPDATEs, count against the same kind
  of budget.

## 4. Consequences

- **The application is shared through `Arc`.** The HTTP/2 driver needs an `Arc<Box<dyn Application + Send>>`, where
  HTTP/1.1's borrows it, so `web_server` builds that once.
- **One frame per live stream,** freed when the stream ends.
- **The encoder compresses less than it could** until M9 decides on dynamic table use.

## 5. Plan and tests (the M7 exit gate, plan §7)

1. **The engine:**
   - HPACK against RFC 7541 Appendix C (done: 16 examples, the integers and Huffman strings, malformed blocks);
   - frames against RFC 9113's layouts (done);
   - the connection state machine: each stream state's legal and illegal frames, flow control, every guard;
   - a fuzz target over the engine.
2. **The driver:** the stream task and `Exchange`'s stream variant, entry by ALPN and by preface, push, drain.
3. **The gate:**
   - `h2spec` 100 %;
   - flow-control and cancel stress (a stream cancelled mid-body; the connection cancelled with 100 streams);
   - `h2load` interop, and `curl --http2` and `nghttp` as clients.
- **Sweeps:** allocation failure and cancellation over `web_http2`'s tests (`tools/run_tests.py`).

## 6. Questions for the owner (answered 2026-11-03)

1. **Entry:** TLS ALPN `h2` and cleartext `h2c` by prior knowledge; no HTTP/1.1 Upgrade.
2. **The client:** server only in M7; the client's HTTP/2 later (Web ADR 0009 keeps it HTTP/1.1 in v0.2).
3. **Priority:** ignored; streams served fairly.
4. **Server push:** supported.

## 7. Amendment 1 (2026-11-03, the driver): how `web_server` serves HTTP/2

- **`Server<S>` is `Server<S: Send>`.** Its routes and middleware are `Box<dyn Handler<S> + Send>` and
  `Box<dyn Middleware<S> + Send>`: each HTTP/2 request runs in its own task (§3.2), so the application crosses tasks.
- **`server.run(…)` takes the server.** It moves it into an `Arc<Box<dyn Application + Send>>` once (§4), through
  `serviceOf(server)`, which gives an `HttpService`: a `ConnectionHandler` that chooses per connection.
  - It chooses HTTP/2 when TLS negotiated `h2`, or when the first 24 bytes are the client preface.
  - It chooses HTTP/1.1 at the first byte that differs from the preface; the bytes read so far go to
    `web_http1.serveFrom`.
  - The reads that choose are held to the header timeout.
  - State a test reads after `run` is shared through an `Arc` (`web_server/tests/support.cee`).
  - `Server<S>` still implements `ConnectionHandler` itself, for HTTP/1.1 by borrow, as before.
- **The handler is lent, not wrapped.** `Box<dyn Application + Send>` lends a `borrow dyn Application + Send`, which
  lends the `borrow dyn Application` that `Exchange` holds. The first draft wrapped the `Arc` in a struct that
  implemented `Application` by calling through the box. That is a cycle through `dyn`, so every request's
  `handle` was a stacked await (CeeSafe ADR 0056), and a failed frame-stack chunk panicked under the allocation sweep.
  Without the wrapper, the sweep is clean. The one-step lend is missing (upstream U19), and the two sweeps disagree on
  that panic (U18).
- **Known gaps:**
  - A client that closes its side (read 0) ends the connection at once, and the set cancels the streams in flight.
    HTTP/2 clients keep the connection open until they have their responses, so this is left for the gate's
    stress tests.
  - Request trailers are not passed to handlers.
