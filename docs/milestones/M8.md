# M8 — Reverse proxy: record

Implementation plan §7 (M8), plus M7's open items (the owner, 2026-11-03). Toolchain: ceesafec **0.11.0** (from stage 3, for U20; stages 1 and 2 were built and tested on 0.10.3). Design:
Web ADR 0012, accepted 2026-11-03 with each of its six recommendations.

**Status (2026-11-04):** on branch `m8-proxy`. The ADR is accepted, with amendment 1 (`Client.run`, the owner's
choice A).
- **Stage 1** is built: the HPACK encoder's dynamic table, request trailers, and half-close. Its h2spec check found
  that M7's "145/145" does not hold on every run. One cause is fixed (`9f0e5ee`); one is a timing case for the owner
  (Findings, below).
- **Stage 2** (the client) is built:
  - a request authority;
  - a response's fields and trailers;
  - a general Upgrade;
  - HTTP/2, with the engine's client role and `Client.run`.
- **Stage 3** (`web_proxy`, on `m8-stage3`) is built, on ceesafec 0.11.0:
  - forwarding fields and trusted proxies; the PROXY protocol, read by the connection worker;
  - choosing backends (smooth weighted round robin, two random choices, rendezvous hashing) and passive and active
    health;
  - the relay: request bodies streamed upstream (U20, resolved by 0.11.0), answers and trailers relayed, 502/503/504
    before the head, an aborted response after it, retries within a budget, upgrades tunnelled;
  - `ReverseProxy.route<S>()` on a route, `handler()` as the whole application; `examples/proxy`.
- The gate's interop checks pass (Runs). The parsers' fuzzer, `tests/fuzz/proxy`, is built; it found a way for a client
  to choose its own address past a trusted proxy, and five departures from the specifications, all fixed (Findings).
  Its 24 CPU-hour run on Debian ended clean. Still to do: the Debian and Windows runs.
- The 24 CPU-hour fuzz run of `web_http2` that M7 owed ended clean.

## Findings

- **Fixed: h2spec §5.1 #10 sometimes read a TCP reset instead of GOAWAY** (`9f0e5ee`). `H2Connection.sendData`
  checked the flow-control allowance before the stream's existence. A stream the client had reset has an allowance
  of 0, so a handler's DATA still on its way gave INTERNAL_ERROR instead of STREAM_CLOSED. The driver treats
  INTERNAL_ERROR as fatal: `serveH2` failed, the worker dropped the socket without `closeGracefully`, and h2spec's
  unread frames made the kernel send a reset. Test: `sends_after_the_peer_reset_are_stream_closed`, which fails
  without the fix.
- **Decided (the owner, 2026-11-04): h2spec §8.1.2.6 #1 and #2 are a timing case, and early responses stay.**
  They fail about 1 run in 10 over TLS and 1 in 4 over h2c.
  - The example's `/` answers without reading the body. If its response is written before the DATA frame whose
    length contradicts `content-length` arrives, h2spec sees HEADERS where it expects RST_STREAM or GOAWAY.
  - The stream is still reset when that DATA arrives.
  - RFC 9113 §8.1 lets a server send a complete response before the request is complete.
  - Holding every response until a body of declared length has ended would pass h2spec, but would delay exactly the
    early answers (401, 413) that §8.1 exists for.
  - The gate's "h2spec 100 %" is therefore read as: every case passes when the response does not race the request's
    body.
- **Fixed (amendment 2): the PROXY protocol's acceptor failed the allocation sweep.** It was an `Acceptor` calling
  its inner one through `dyn Acceptor`. That is a stacked await (CeeSafe ADR 0056), and allocation 9 of
  `the_acceptor` hit ADR 0056 §3.3's panic. On the owner's choice the connection worker reads the header instead,
  with no cycle. The worker test (`the_worker_reads_proxy_headers`) and the parser tests then have no failures in 105
  and 167 allocation-sweep runs.
- **Fixed: a request could wait forever when an HTTP/2 connection failed out of memory** (`754d2bd`, `web_client`).
  Found by the full run's allocation sweep: `two_requests_share_a_connection` timed out at allocations 86–123.
  - A connection that failed before its first frame left its command queue open.
  - A start `run` could not spawn a task for was dropped.
  - A stream that could not be opened or kept was never told.
  - A stream's inbox was dropped, not closed, so a request whose last part did not fit never saw the end.
  Each now tells the request and closes its channels; with the old driver the same allocations still hang.
- **Fixed: `/` never matched a root wildcard** (`web_server`, from M2). `Router.find` returned the root node for `/`
  even without routes there, so `/*path` (how `examples/proxy` mounts the proxy) gave a 405 with an empty `Allow`.
  Web ADR 0007 §3.3 and the existing tests let a wildcard be empty (`/files/` matches `/files/*rest`). Test:
  `a_root_wildcard_matches_the_root`, which fails without the fix.
- **Fixed: two `Date` fields in a proxied response** (`web_http`). The writer added its own `Date` beside the one the
  proxy relayed; RFC 9110 §6.6.1 gives a response one. A handler's `Date` now stands, over HTTP/1.1 and HTTP/2. Tests:
  `a_head_date_is_the_only_date` (the encoder) and `a_handler_date_is_the_only_date` (HTTP/2's heads, HPACK-decoded),
  which fails without the fix.
- **Fixed: a client could choose the address it is known by** (`b860e22`, `web_proxy`; found by `tests/fuzz/proxy`'s
  invariant 6).
  - A trusted proxy that extends the `Forwarded` field it received (nginx's `$proxy_add_forwarded`, and this proxy's
    own `forwardingFields`) appends its hop after the client's bytes.
  - The splitter toggled on every `"`, so an unclosed quote in the client's bytes, such as
    `for=203.0.113.9;x="`, swallowed the appended `, for=198.51.100.241`. The client's own `for=` was then the
    right-most hop, and `clientOf` named 203.0.113.9; with `for=_x`, the client hid.
  - A field that ends inside a quoted string cannot be split, so its last hop is now malformed and the walk stops at
    the trusted peer (Web ADR 0012 §3.4). A proxy's hop in a field of its own is read whatever the client's holds.
  - Test: `a_client_cannot_swallow_the_trusted_hop`, which fails without the fix.
- **Fixed: `Forwarded` read quoted strings and lists more narrowly than RFC 9110 §5.6** (`b860e22`). A `\"` ended a
  quoted string (§5.6.4 makes it a quoted-pair); a `for` value was not unescaped (RFC 7239 §5.2: "after potential
  quoted-string unescaping"); an empty list element was a malformed hop (§5.6.1.2: "MUST parse and ignore"). A second
  `for` in one element is now malformed (RFC 7239 §4). Test: `quoted_pairs_and_empty_elements`.
- **Fixed: the PROXY protocol's parser departed from proxy-protocol.txt** (`b860e22`, `web_transport`).
  - v1: after `UNKNOWN`, two spaces or more than five fields were refused; §2.1 says the receiver "must ignore
    anything presented before the CRLF".
  - v2: an unassigned family or transport was accepted, where §2.2 says such values "must be rejected as invalid by
    receivers". Addresses over the UNSPEC transport were used, where "the receiver should ignore address
    information". An AF_UNIX block shorter than its two 108-byte addresses was accepted, though "the receiver must
    also reject incoming connections containing partial protocol headers".
  - A zone was let through as `%0`, which lib/std parses as scope 0, in a TCP6 address, a CIDR block and a
    `Forwarded` node. Any `%` is now refused.
  - Tests: `unknown_ignores_the_rest_of_its_line`, `version_2_families_and_transports`, and new cases in `version_1`
    and `blocks_rfc4632`.
