## Open findings

- **h2spec §8.1.2.6 #1 and #2 depend on timing.** The example's `/` answers without reading the body. If its response
  is written before the DATA frame whose length contradicts `content-length` arrives, h2spec sees HEADERS where it
  expects RST_STREAM or GOAWAY. RFC 9113 §8.1 allows a server to respond before the request is complete. The stream
  is still reset when the DATA arrives. To be decided: whether the driver should hold a response's END_STREAM until a
  request body with a declared length has ended, or whether this stays a documented h2spec timing case.
- **h2spec §5.1 #10 sometimes gets a TCP reset instead of GOAWAY.** That is a real fault: a client may lose the
  GOAWAY that explains the close. The cause is being traced. The connection error path does return through
  `Transports.closeGracefully`, so the reset comes from somewhere else.
