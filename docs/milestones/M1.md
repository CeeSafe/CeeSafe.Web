# M1 — Transport and connection lifecycle: record

Implementation plan §7 (M1), with the owner's decision of 2026-11-02: **connection workers (option A of
`docs/milestones/M0.md`) for M1–M3**; spawning into a running scope (U11) is proposed upstream before M7.

**Where it lives:** main, with ceesafec **0.7.0** (`docs/toolchain.md`). It was built on branch `m1` against 0.6.0,
where CeeSafe bug B2 kept every native program that imports `web_core` from building; 0.7.0 fixed B2 (and B1, B3,
B4) and shipped U1–U4 and T1, so the branch was moved to 0.7.0 and merged.

## Design (workers)

`ConnectionServer.run(incoming, acceptor, handler, limits, drain)` (`packages/web_transport/src/server.cee`):

- `limits.workers` workers in one scope, each looping: race `incoming.next()` against the drain → `acceptor.accept`
  with the handshake deadline → `handler.serve(conn, ctx)` → a graceful close (`Transports.closeGracefully`, bounded by
  `closeLingerMs`).
- **Admission is the worker count.** When every worker is busy, nobody accepts, and the kernel's backlog holds the
  rest. (Accept-and-close with a 503 when full needs an overflow acceptor; it is deferred to M2, where the 503 is
  written.)
- **A failure ends its connection only.** Handshake failures, handler errors and accept errors are counted
  (`ServerReport`); an accept error pauses the worker for `acceptBackoffMs` (descriptor exhaustion). Only
  cancellation and out-of-memory in accept end a worker.
- **Drain** (`web_core` `Drain`, Web ADR 0001 amendment 2): starting it wakes every worker waiting in accept, and they
  return. Connections in flight finish. A handler between requests races its idle wait against `ctx.drain()` and
  returns `Ok`. After `graceMs`, a race in `run` cancels the workers' scope (`forced` in the report).
- `Incoming` is an interface, implemented by `Listener` (TCP) and `MockIncoming` (a channel of scripted
  `MockTransport`s), so the whole lifecycle is tested deterministically in the interpreter.
- Deadlines: `Transports.readWithin`/`writeWithin`, and `MinRate` for slow senders (`web_core`). `ConnectionLimits`
  carries the defaults (header and handshake 10 s, idle 60 s, write 30 s, 240 B/s after 5 s, 16 KiB buffer, 1 s
  linger, 30 s grace). Kestrel's minimum data rate (240 B/s, 5 s grace) is the source of those two.

`tests/web_transport/server` covers:
- 12 connections at seeded splits through 4 workers, with every echo matched and at most 4 served at once;
- a reset at each of 27 offsets and a write failure at each of 26, each failing its connection only, while the server
  goes on serving;
- a stalled handshake timing out;
- a drain: it stops 8 idle workers at once, lets requests in flight finish, closes idle keep-alive connections, and
  cancels connections that ignore it once the grace runs out (shutdown within drain + grace + ε);
- 8 real TCP clients through 4 workers, then a drain; each handler's context has the loopback peer and the
  listener's port;
- a real RST (`TcpTransport.abort`, SO_LINGER 0) while the handler reads: the read is `Err(Reset)`, the connection
  counts as failed;
- descriptors back to the baseline (`/dev/fd`) after the run.

`tests/web_transport/tcp` adds an IPv6-only listener on `::1` with a backlog of 64 (`bindWith`), a client connecting
to its `localAddress()`, and each end seeing the other's address. `tests/web_core/errors` checks the new mappings.

## Memory per connection (`--explain-frames`, `tests/web_transport/server`)

| Frame | Bytes |
|---|---|
| `worker` (a whole connection: accept, handshake, serve, close) | **3024** (0.6.0: 2880; the context now holds both addresses, 88 bytes) |
| of which: the room for `dyn ConnectionHandler.serve` (sized by the largest handler in the program, `EchoHandler.serve`) | 1584 |
| `Transports.readWithin` (`Async.deadline`; 0.6.0's race: 1296) | 1168 |
| `Transports.writeWithin`, `closeGracefully` (races, until B6) | 1248 each |
| `PlainStream` boxed on the heap | 144 with 0.6.0; now larger by `TcpTransport`'s two `SocketAddress?` (not re-measured) |
| `ConnectionServer.run` (once per server) | 1120 |

So with a small handler an idle connection costs about **3 KiB** plus the socket, against 1.1 KiB for M0's bare echo
loop. The growth is the deadline bounds: `Async.deadline` is lowered as a race (CeeSafe ADR 0046 §3), so each still
holds the operation's frame and a timer's inline, and released 0.7.0 saved only 128 bytes on `readWithin`. An
HTTP/1.1 driver (M2) adds its own frame inside the handler room; measured with a real driver in M2.
