## Baseline: memory per connection

`tests/web_transport/workers`, built with `ceesafec build --explain-frames` (0.6.0):

| Frame | Bytes |
|---|---|
| `worker` (accept → serve loop, whole connection task) | **920** |
| `serveOne` (inside it: the echo loop, a 32-byte buffer) | 664 |
| `dyn Transport.read` await room (largest: `PlainStream.read`) | 520 |
| `PlainStream` boxed on the heap (`Box<dyn Transport>`) | 144 (`PlainAcceptor.accept`'s `v_stream`) |

So an idle plain connection costs about **1.1 KiB of CeeSafe memory** plus the kernel socket, with no read buffer held
(HTTP/1.1 will add its pooled head buffer, Web ADR 0003 §3.1).

## Findings

1. **CeeSafe 0.6.0 does not contain U1/U2** (tag `v0.6.0` predates ADR 0044's commits). Peer addresses and the reset
   error kind are deferred to the release that ships them (Web ADR 0001, amendment 1).
2. **CeeSafe bugs found**, with repros in `tests/probes/` and write-ups in `docs/ceesafe-upstream-work.md`:
   - **B1:** an `@effectsOf` async fn called with an async closure gives wrong values in the interpreter and calls a
     null pointer natively;
   - **B2:** an unused socket type's drop function is missing from the generated C;
   - **B3:** const discarded for a race child's captured array (a C warning).
3. **Language limits designed around** (Web ADR 0001 amendment 1):
   - no slices of slices, hence `IoParts`;
   - no method type parameters;
   - `@effects()` needed for sync `dyn` methods called from async code;
   - `PoolBox` cannot be stored in a field.
4. **A scope cannot spawn after its body (spec §40.5), so there is no task per accepted connection.** The worker
   pattern works and is bounded (`tests/web_transport/workers`), but it changes M1 and M7. See the decision below.

## Decision needed before M1

**How do connections (and HTTP/2 streams) get tasks?**

| | A. Connection workers (works today) | B. Upstream U11: spawning into a running scope |
|---|---|---|
| Shape | N workers, each `accept → serve` in a loop; N = the connection limit | one task per connection, spawned by the accept loop; a bound on live tasks |
| Memory | N × ~1 KiB reserved up front (64k connections ≈ 70 MiB) | per live connection only |
| Admission | by construction: the kernel backlog holds the rest | a bounded spawn that waits or fails when full |
| HTTP/2 | M workers per connection, fed streams through a bounded channel | a task per stream |
| Cost | none upstream | an ADR and runtime work in CeeSafe |

**Recommended:** A for M1–M3, which needs nothing upstream and is bounded by design, with B proposed to CeeSafe as
U11 before M7, where per-stream tasks matter most.
