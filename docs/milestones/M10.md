# M10 — HTTP/3 and QUIC: record

Implementation plan §7 (M10). Design: Web ADR 0014, accepted 2026-11-09 with the owner's seven answers. Toolchain:
ceesafec **0.22.0**; OpenSSL ≥ 3.5 for `web_quic` only. ngtcp2 **1.26.0** and nghttp3 **1.19.0**, vendored.

**Status (2026-11-09):** in progress, on branch `m10-h3` (draft pull request #6).
- **Stage 1 is done.**
- **Stage 2's first part is done:** the shim's connection path, the counted allocator, and the loopback handshake.
- **Stage 2's second part is done:** the UDP driver, connection-ID routing, and hq-interop, tested over real UDP on
  kqueue, epoll, io_uring, IOCP and WSAPoll.
- **Next:** interop with ngtcp2's example client.

## Stage 1: vendoring and the build (2026-11-09)

- **`tools/vendor_quic.py`** vendors ngtcp2 1.26.0 and nghttp3 1.19.0 into `third_party/` (2.8 MB):
  - it checks each release tarball against GitHub's recorded SHA-256 (`third_party/README.md`);
  - it copies only the compiled sources (48 and 32), their headers and their MIT licences;
  - it writes a portable `config/config.h` for each, and one wrapper per source in each package's `c/vendor/`.
  - **The wrappers exist because manifests pass no defines.** Each wrapper sets what the libraries' own build would:
    `HAVE_CONFIG_H`, the static-library macro, and `_GNU_SOURCE` on Linux. Then it `#include`s the untouched
    original.
  - **`config.h`** detects the system with the preprocessor. Only optional faster paths depend on it, and each
    library has a portable fallback (`ngtcp2_net.h`, `nghttp3_conv.h`). The libraries test `WIN32`, which compilers do
    not define, so `config.h` defines it on Windows.
- **`web_quic` (new):**
  - its shim (`c/quic_shim.c`) refuses OpenSSL < 3.5 at compile time and reports the versions;
  - its include path is upstream's for the crypto sources (`lib/` and `crypto/`, from `crypto/ossl/CMakeLists.txt`);
  - it links OpenSSL per system as `web_tls` does.
- **`web_http3`** depends on `web_core`, `web_http` and `web_quic` (Web ADR 0004 amendment 4). It has its own shim
  (`c/h3_shim.c`).
- **CI:**
  - Linux moves to `ubuntu-26.04` (OpenSSL 3.5.5), for the sweeps and io_uring;
  - one `ubuntu-24.04` job keeps OpenSSL 3.0 tested, sweeps included, without the two QUIC packages;
  - `tools/run_tests.py` gains `--exclude`.
- **On hanan:** OpenSSL 3.5.9 built into `/root/cw-m10/openssl-3.5`, a prefix that installs nothing system-wide (the
  owner's answer 5).
  - The release tarball matched GitHub's SHA-256 digest.
  - It was configured with `--prefix=/root/cw-m10/openssl-3.5 --libdir=lib shared no-tests`.
  - Builds there set `CPATH`, `LIBRARY_PATH` and `LD_LIBRARY_PATH` to the prefix, so the manifests are unchanged.

The tests: `web_quic`'s `ngtcp2_is_the_vendored_release`, `openssl_is_at_least_3_5` and
`the_openssl_backend_initialises`; `web_http3`'s `nghttp3_is_the_vendored_release`. Expected values: the release

- **Warnings:** on Windows, the one warning is CeeSafe's own runtime's (`ceesafe_rt_io.c:399`, as in M9), none from the

- **Every package:** `check`, `fmt --check` and `doc --missing` are clean, and `tools/check_layers.py` passes (14
  packages).

**Moved to stage 2, and why:**
- **The allocator** (`ngtcp2_mem`, `nghttp3_mem` over `CEE_ALLOC_FOREIGN`) is passed per connection. Stage 1 creates
  none, so it would be unused, untested code.
- **The loopback handshake** needs the shim's connection path, which is stage 2's first part.
- Stage 2 starts with both.

**Open for stage 3:**
- ADR 0014 §3.1 has `web_server` gain `web_http3` "behind an option". But a manifest's dependency is not optional, so
  every server would then link ngtcp2 and OpenSSL 3.5.
- The likely fix is for `web_http3` to depend on `web_server` and serve its application, as `web_proxy` and
  `web_static` do. That is an amendment to settle when stage 3 starts.

## Stage 2, first part: the connection path (2026-11-09)

- **`web_quic/c/quic_shim.c`** implements Web ADR 0014 §3.4, with amendment 1:
  - TLS contexts from `web_tls`'s configuration;
  - client and server connections;
  - `qs_read`, `qs_write`, `qs_close` and the timers;
  - streams with held send buffers, a bounded event queue, error classification, and ngtcp2's allocator over
    `CEE_ALLOC_FOREIGN`.
- **`web_quic/src/connection.cee`** holds `QuicTls`, `QuicConnection`, `QuicAddress`, `QuicIds`, `QuicEvent` and
  `QuicError`. It is sans-I/O: the caller's clock, and no sockets.
- **`web_tls` (Web ADR 0002 amendment 6)** has its own SSL slot for a server's configuration, which fixes the ticket
  callback's use of app data, plus `wt_init`, `wt_ssl_use_front`, `TlsConfig.quicContext()` and `Alpn.Http3`.

### Tests run (2026-11-09, ceesafec 0.22.0)

- **`web_quic`'s `handshake_stream_echo_and_close`:** a client and a server in memory, on a fake clock. Expected
  outcomes are RFC 9000's and RFC 9001's. It checks:
  - the handshake completes on both sides;
  - ALPN `h3` is chosen;
  - the client's first stream is 0 (§2.1), and its bytes arrive whole with the FIN;
  - the server echoes them, and the client receives them whole;
  - after the client's CONNECTION_CLOSE, the server is draining (§10.2).
  - The server's certificate is the test CA's "localhost", verified by the client.
- **On every system:**

  | System | OpenSSL | web_quic | web_tls | web_http3 |
  |---|---|---|---|---|
  | macOS arm64 | 3.6.4 | 4 passed | 17 passed | 1 passed |
  | Debian 12 (hanan) | 3.5.9 prefix | 4 passed | 17 passed | 1 passed |
  | Windows 11 ARM64 | 4.1.0 | 4 passed | 17 passed | 1 passed |

  Debian's gcc gave no warning once the two new web_tls exports were declared before use.
- **Sanitizers and sweeps (macOS):**
  - `run_tests.py --sanitize --alloc-sweep --cancel-sweep` gave web_quic 4 passed, with 0 failures in 224 sampled
    allocation-sweep runs, and web_tls 17, with 0 failures in 3390 allocation and 913 cancellation runs.
  - `ceesafec test --sweep alloc` samples past 200 allocations (CeeSafe ADR 0049 §3.3), and the handshake makes 6868.
    So every one was also failed in turn under ASan and UBSan, with the harness's fail-at argument (a scratch script,
    `full_sweep.py`, not committed).
  - **That gave 6868 runs:** 3260 passed with the failure absorbed (by OpenSSL, or by QUIC's retransmission), 3608
    failed cleanly, and **0 crashed, reported a sanitizer error or leaked**.
  - A first attempt set `CEESAFE_FAIL_ALLOC_AT`, which the harness's argument overrides, so it injected nothing. It is
    not counted.
- **Found and fixed along the way:**
  - **web_tls's ticket callback read QUIC's app data.** That was the cause of the first NGTCP2_ERR_CRYPTO.
  - **The ticket callback's fix freed the BIOs twice** when an allocation failed. web_tls's sweep found it, with 12
    failures before the fix.
  - **OpenSSL's allocations went uncounted** when ngtcp2 initialised first.
  - **Three hand-copied ngtcp2 error codes were wrong**, and the event queue truncated data.

**Next in stage 2:** the driver (`AsyncUdpSocket`, connection-ID routing, Initial admission, timers per connection),
stateless resets, and interop with ngtcp2's example client.

## Stage 2, second part: the driver and hq-interop (2026-11-09)

- **`web_quic/src/server.cee`:** `QuicServer.serve`, `QuicServerOptions`, `QuicApplication` and `QuicLink`. It has a
  listener task, connection tasks and connection-ID routing (Web ADR 0014 amendment 2 item 3).
- **`web_quic/src/hq.cee`:** `HqFiles`, a server for hq-interop (amendment 2 item 4).
- **The shim** has two changes, each found over real UDP (amendment 2 items 1 and 2):
  - its event queue's bound is now flow control's, and `QuicError.WouldBlock` is removed;
  - a stream's sent bytes are held in chunks that never move.

### Tests run (2026-11-09, ceesafec 0.22.0)

- **`hq_interop_transfer_over_udp` (new):** `QuicServer` with `HqFiles` over real UDP sockets on loopback. The client
  is the test's own `QuicConnection`, which asks for three files on three streams:
  - `/small.txt`, 1000 bytes;
  - `/large.bin`, 3 MiB, more than a stream holds unacknowledged, so the server waits on `StreamWritable`;
  - `/missing`, which gets an empty answer.
  - The expected bytes are the files', which the test wrote (`pattern`).
- **`lossy_transfer_is_whole_and_in_order` (new):** 3 MiB on one stream in memory, with every fifth datagram dropped
  in both directions. It expects every byte, in order (RFC 9000 §2.2, RFC 9002).
- **On every system and reactor** (web_quic's 6 tests per run):

  | System | Reactor | Runs | Result |
  |---|---|---|---|
  | macOS arm64 (OpenSSL 3.6.4) | kqueue | 1 | 6 passed |
  | Debian 12, hanan (the 3.5.9 prefix) | epoll | 5 | 6 passed in each |
  | Debian 12, hanan | io_uring (`CEESAFE_REACTOR_URING=1`) | 5 | 6 passed in each |
  | Windows 11 ARM64 (OpenSSL 4.1.0) | IOCP | 3 | 6 passed in each |
  | Windows 11 ARM64 | WSAPoll (`CEESAFE_REACTOR_POLL=1`) | 11 | 6 passed in each |

  - The Windows WSAPoll count is 11, not 3: a cmd loop meant as 3 IOCP runs and then 3 WSAPoll runs nested the second
    loop inside the first. That left 1 IOCP run and 11 WSAPoll runs, so the other 2 IOCP runs were made separately.
- **Sanitizers and sweeps (macOS):** `run_tests.py --sanitize --alloc-sweep --cancel-sweep` on web_quic gave 6 passed,
  with 0 failures in 624 sampled allocation-sweep runs and 200 cancellation-sweep runs.
- **Sanitizers on Debian:** `hq_interop_transfer_over_udp` under ASan and UBSan was clean in 3 of 3 runs.
- **Every package:** `check`, `fmt --check` and `doc --missing` are clean with ceesafec 0.22.0, and
  `tools/check_layers.py` passes (14 packages).
- **Found and fixed along the way:**
  - **The event queue overflowed** on epoll and WSAPoll: ngtcp2 error -228 when a repaired loss released the data
    held behind it (amendment 2 item 1). macOS's kqueue runs had not shown it.
  - **Retransmissions sent wrong bytes:** the send buffer moved bytes ngtcp2 still pointed into (amendment 2 item 2).
    Evidence that the fix is what matters:
    - with the old buffer restored (a scratch script, `stream_revert.py`, not committed), the transfer and lossy tests
      fail on Debian and macOS, and pass with the fix;
    - on Windows before the fix, `hq_interop_transfer_over_udp` failed in every run on IOCP and WSAPoll (4 passed, 1
      failed, before the lossy test existed).
    - ASan reported no use-after-free in the runs with the old buffer: the moved bytes stayed inside live allocations,
      so the evidence was the wrong bytes.

**Next in stage 2:** interop with an external client (ngtcp2's example client, built from the vendored sources).
Stateless resets are stage 4's (§4).
