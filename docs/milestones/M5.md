# M5 — HTTP client: record

Implementation plan §7 (M5). Toolchain: ceesafec **0.9.2**. Design: Web ADR 0009, accepted 2026-11-02 (each question
as recommended: trusted `web_tls` for a `Send` pool, POST becomes GET after 301/302, HTTP/1.1 only in v0.2).

**Status (2026-11-02):** the client is written and its gate tests pass in the interpreter, but it waits for CeeSafe
**B15**: async calls through `dyn I` and `dyn I + Send` collide in C, so nothing with a `Box<dyn Transport + Send>`
builds natively. On main: the engine, `Url`, and trusted `web_tls`. On branch `m5-client`: `web_client`, and
`Connector` returning `Box<dyn Transport + Send>`.

## Delivered

| Where | What |
|---|---|
| `web_http1` (main) | `parseResponseHead` (strict status line, the shared field rules, RFC 9112 §6.3 framing, keep-alive), `ResponseBody`, `ParsedResponse`, `RequestWriter` (every part checked: no header injection). `parseFields` shared with the server |
| `web_http` (main) | `Url` (absolute http/https; RFC 3986 §5.2 resolution), `ProtocolError.BadStatusLine` |
| `web_tls` (main) | `trusted = true`; `TlsConfig`, `TlsTransport`, `TlsSession` `@threadSafe` (Web ADR 0009 §1) |
| `web_client` (branch `m5-client`) | `Client` (`create`, `withNetwork`, `get`, `send`, `shutdown`), `ClientRequest`, `BodySource`, `BytesBody`, `NoBody`, `ClientResponse` (`status`, `header`, `url`, `read`, `readToEnd`, `finish`), `ClientOptions`, `RetryPolicy`, `ClientError`; the pool; `Resolver`, `Dialer`, `happyEyeballs`, `interleave` |
