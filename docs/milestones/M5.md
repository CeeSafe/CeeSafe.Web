# M5 — HTTP client: record

Implementation plan §7 (M5). Toolchain: ceesafec **0.9.4** (minimum: B15's fix). Design: Web ADR 0009, accepted
2026-11-02 (each question as recommended: trusted `web_tls` for a `Send` pool, POST becomes GET after 301/302,
HTTP/1.1 only in v0.2), amendment 1 (2026-11-03).

**Status (2026-11-03): done.** The client waited on branch `m5-client` for CeeSafe B15 (async calls through `dyn I`
and `dyn I + Send` collided in C). 0.9.4 fixed it, and every gate below passed on macOS, Debian 12 and Windows 11.

`web_client`'s 12 tests:
- a GET with a chunked body;
- **no POST replayed after a partial write, at each of the 68 splits**;
- a GET retried only when nothing went out;
- a server close during reuse: the GET is retried on a new connection, the POST fails;
- DNS failure dials nothing;
- first-byte and connect timeouts;
- Happy Eyeballs: a slow IPv6 address loses to IPv4 after 250 ms, and a failing one starts the next at once;
- RFC 8305 address order;
- redirects: 303 turns a POST into a GET, a cross-origin 301, the limit;
- shutdown: later requests refused;
- **shutdown with requests in flight**: a waiter for a slot ends with `Shutdown`, a response being read finishes on
  its own connection, and that connection is closed rather than pooled;
- bad requests.

The interop checks (`tests/interop/client.py`, expected values from RFC 9110 §15.4, RFC 9112 §6–7 and Web ADR
0009 §3.4–3.7, observed on the server's side where they can be):
- GET, with the authority as Host; a chunked body; a body read to the connection's end; POST with a body;
- three GETs over one connection;
- a server that closes a kept-alive connection: both GETs succeed, on a second connection;
- POST then 301, 302 and 303 arrive as GET, and 307 and 308 as POST with the body, each request sent once;
- a cross-origin redirect, with the new authority as Host;
- the redirect limit: the 11th response, a 302, is the answer;
- connection refused, and DNS failure;
- https against Python's `ssl`: chunked, and reuse;
- a certificate from an unknown CA, and one without the name, are refused;
- `examples/https`: GET twice and POST.

## Found while closing M5

| Finding | Fix |
|---|---|
| `trustSystem` on Windows rejected public servers: OpenSSL's defaults do not reach the system's store | the shim also loads `org.openssl.winstore://` (Web ADR 0002 amendment 4) |
| gcc warned 32 times in the shim (`-Wmissing-prototypes`) and once (`-Wcast-qual`), since M4; M4's Debian record missed it | prototypes for the exports; no cast in `wt_peer_names` |
| `web_transport`'s `four_workers_serve_twelve_clients` failed on Debian (0.9.2 too): one worker drained all 12 connections before another woke. A probe holding each connection 100 ms spread them 3/3/3/3 on Debian and macOS, so no worker starves | each connection holds its worker 20 ms, so the test's claim (more than one worker serves) is about concurrency, not timing |
| `examples/fetch` reports a DNS failure as "No such file or directory" | upstream **U15** (`docs/ceesafe-upstream-work.md`) |
